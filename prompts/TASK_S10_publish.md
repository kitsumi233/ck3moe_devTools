# TASK S10：发布前检查与打包

用法：先贴 `00_START_HERE_for_AI.md`，再贴本文件，并附上 `LESSONS_5_build_verify_ops.md` 的“发布与外部平台（通用流程）”和“当前状态提醒”。

## 提示词

你要把已验收的基础包整理成可发布的拷贝。**本任务只做到“生成拷贝并核对”，不做任何上传。** 上传、登录、改线上描述都由所有者在自己的窗口里完成。

### 先读

- `PIPELINE.md` 的 S10 一节。
- `LESSONS_5` 里关于“工坊内容可能比仓库新”和“多语言描述的静默陷阱”的两条。
- 当前约定：`mod/` 以创意工坊版为底；任何会整目录替换或重建的步骤，都必须先确认仓库副本没有落后。

### 步骤

1. 发布前比对：把线上最新的订阅副本与 `mod/` 逐文件比对（大小与哈希）。有差异先同步回仓库并备份，不要从落后的仓库发布。
2. 确认输出根里 descriptor 与缩略图已就绪。`publish_mods.py` 只做 `finalize_mods.checks()` 自检，不会替你跑 finalize；而 `finalize_mods.py`（即使 `--no-sync`）会改写输出根，所以只能对拷贝出来的目录运行，并且要先得到所有者同意，不要直接对 `mod/` 运行。
3. 出发布拷贝：`python tools/build/publish_mods.py --dest <空目录> --only <mod 名...>`。必须显式给 `--dest`，不要用脚本默认值（它指向本机的文档目录）。
4. 核对拷贝：每个 mod 的 `descriptor.mod` 版本号已升；外层 `.mod` 的 `path` 指向正确；被省掉的未引用动画数量与 `work/runtime_animation_selection.json` 一致。
5. 如需 Core 以外的包，体积是几个 GB 一个，单独向所有者确认。

### 验收（逐项给出实测值）

- 拷贝目录里没有 `__pycache__`、日志、临时文件。
- 拷贝目录里没有任何账号、密码、令牌、服务器地址、代理地址（扫一遍）。
- 依赖顺序：模型包依赖 shader 和核心；核心不依赖任何模型包。
- 原模型若禁止二次配布，已提醒所有者。

### 不要做

- 不要执行上传命令，也不要登录任何平台账号；需要登录时请所有者自己操作。
- 不要在内容清单里写 description，否则会覆盖线上描述。
- 不要把 `publish_mods.py` 的目标指到含有用户其他 mod 的目录并整目录替换。
- 不要把工程里的 `work/`、`assets/`、`trash/` 打进发布包。

### 汇报

按 `00_START_HERE_for_AI.md` 的汇报格式，并附上：拷贝目录、每个 mod 的文件数与体积、版本号、与线上副本的差异清单、需要所有者决定的事项。
