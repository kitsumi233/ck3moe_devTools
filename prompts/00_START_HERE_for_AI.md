# 00 给 AI 助手的总说明

用法：每次开新任务，先把本文件整段贴给 AI 助手，再贴对应阶段的 `TASK_S*.md`，最后附上该阶段指定的 `LESSONS_*.md`。本文件定义通用规则，阶段文件只写阶段内容。

## 提示词

你在帮一个 CK3（Crusader Kings III）“萌化”mod 项目干活。项目把 MMD 的 PMX 角色模型做成游戏里的肖像：拆出头和身体网格，把表情烘成骨骼动画，把原版动作重定向到角色骨架，生成 mod 文本，再烘头发和裙子的物理。你手里有一个 `tools/` 脚本集、`PIPELINE.md` 流水线说明、`MANIFEST.md` 文件清单，以及按主题整理的教训。

### 术语

- `ck`：角色短键，如 `lau`。`slug`：仓库侧的长名，如 `endfield_laurentina`，只用于 `work/<slug>/` 目录和盘点 JSON。`moe_<ck>_`：进 mod 的资源前缀。三者都登记在 `tools/lib/moe_chars.py` 的 `CHARS`，加角色只改这一处。
- `.mesh`、`.anim`、`.asset` 是 CK3（PDX 引擎）的二进制网格、二进制动画和文本资产声明。`.anim` 文件头写死骨数，必须与它所属 entity 的 mesh 骨数严格相等。
- head / torso：头和躯干是两个独立 entity，各播自己的动画，必须一对一同名配对。
- state 和 animation id 是两套命名空间；循环靠 `next_state` 自跳转，不靠 `looping = yes`。
- 载体架构：CK3 1.20 起，真网格做成配件，由只有一个退化三角形的骨架载体带动画（`build/carrier_pipeline.py`）。
- 隔离 userdir：测试只用 `work/ck3_florence_userdir`，不用玩家日常的 userdir。

### 通用规则

1. 先读后动。动手前读 `PIPELINE.md` 里对应的一节和阶段文件指定的 `LESSONS_*.md`。教训是时间点观察，标了“已取代”“有张力”的条目以实机为准。
2. 不要对 `mod/` 跑生成器。`build_moe_mod.py` 开头会清空整个 mod 目录，`build_all.py` 全流程、`finalize_mods.py`、`publish_mods.py` 同理会改写或发布它。需要生成时，把环境变量 `MOE_OUT_ROOT` 指到沙盒目录。有人手改过的 `mod/` 要就地改文件，保持 BOM 与 CRLF。
3. 构建失败就停。不要把“构建 + 装机 + 启动”写成一行；自检失败是真问题，不要绕过去装机。
4. 长任务只监控，不自己停。烘焙、全量重定向这类任务，内存紧张也只报数字和建议，由用户决定。不要终止不是你启动的进程，尤其是别人正在用的预览服务和烘焙。
5. 长链用独立 console 启动（Windows 的 `Start-Process`），监控要同时匹配成功和失败，到期要重挂。
6. 已发布角色的目录不可变。动基础动画前先看 `X.bake_dir(ck)` 是否落在发布修订路径下，是的话写暂存目录再移植。
7. 验收以数值和游戏日志为准。本地渲图正常不等于验收通过：骨数不匹配、缺 meshsettings、缺 `portrait_modifier`、材质路径带目录，都只在游戏的 `error.log` 里报。查日志前先确认进程启动时间晚于改动，`grep` 要加 `-a`。
8. 找到上游根因再改。发现缺陷，改产生它的那一步，不要写脚本去补已导出的产物。本包的脚本和原工程逐字节一致；要改脚本，先说明理由，并让原作者知道。
9. 脚本里的硬编码盘符（`D:`、`E:`、`F:`、`C:`）是原作者机器的，见 `MANIFEST.md`。不要擅自重写，先问路径，改完记下改了哪几行。
10. 不要在任何文件、日志、提交信息里写入账号、密码、令牌、密钥、服务器地址、代理地址。需要登录平台时，请用户在自己的窗口操作。
11. 产物里不留第三方参考实现的痕迹：骨名、注释、拷贝的二进制、原样参数都用自己的。
12. 临时文件放系统临时目录并在结束前清掉。不要往工程里留 `__pycache__`（import 检查用 `python -I -B`）。

### 工作方式

- 先说你打算跑什么命令、会写哪些目录，再动手。会写 `work/` 之外的命令必须先确认。
- 给出的数字必须是你测出来的；没验证过的不要写成已完成，写成“未验证”。
- 零报错的静默失效是这个项目最常见的坑。每个结论配上证据：日志关键字、像素或权重统计、文件数、哈希、骨数。

### 汇报格式

先一句话结论，然后依次给：做了什么（命令与写入目录）、验收判据与实测结果、没把握或没验证的地方、下一步建议。
